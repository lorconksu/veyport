# Protobuf generation and compatibility

Run `make proto` to regenerate Go from every schema under `proto/` and
`make proto-check` to verify the committed generated bytes without changing files.
`PROTO_BASE_SHA=<full-commit-sha> make proto-breaking` checks schema compatibility.
Without a SHA, the latter resolves `origin`'s `main` once and compares against that
exact commit. CI supplies the GitHub event's exact PR base or previous push SHA;
non-PR reusable callers without either resolve upstream `main`.

`python3 scripts/proto/check.py ci` combines reproduction, Buf build/compatibility,
and behavioral fixtures in the existing CI unit job before Go tests. Fixtures
verify rejection of generated drift, field deletion and field renumbering, allow
an additive field, and verify exact-base fetching in a shallow checkout while
excluding baseline executable files and configuration. A missing schema baseline
or invalid/zero comparison SHA fails closed. Only `.proto` blobs are read from the
comparison commit; its generation commands, scripts, and Buf config never run.

Python 3, Git, and Go are required, with network access to official release
downloads, the Go module proxy, and the public checksum database. Linux amd64 and
arm64, and macOS amd64 and arm64 have pinned release hashes. Only Linux amd64 is
exercised in CI. Downloads are verified before execution and fresh temporary
executables are removed after each command; system protobuf tools are ignored.

`tools.py` pins protoc 21.12 (which reports 3.21.12), protoc-gen-go 1.36.11, and
protoc-gen-go-grpc 1.6.2 to preserve the existing generated files exactly. The Go
plugins have pinned module `h1` checksums and require public Go checksum database
verification, including their transitive modules; private/no-sumdb overrides are
cleared. Protoc SHA256 pins were measured from the official v21.12 release ZIPs;
that historical release has no publisher checksum manifest or API asset digests.
These pins detect changed downloads, but do not claim a separate publisher
signature or attestation. Buf SHA256 pins were checked against the official
v1.61.0 `sha256.txt` and GitHub release asset digests. Links to official releases
are beside the pins.

Buf 1.61.0 is a development-only dependency justified by descriptor-aware schema
comparison, which generated byte comparison cannot provide. Its conservative
`FILE` category protects generated source, JSON, and wire compatibility without
exceptions. Buf is Apache-2.0 licensed; protoc and the existing Go generators use
BSD-3-Clause and Apache-2.0 licenses. The new maintenance/supply-chain surface is
one pinned Buf executable, downloaded only for schema checks, with no runtime or
Go module dependency added. Updating any pin requires reviewing its official
release, refreshing/verifying checksums, and rerunning the control fixtures;
updating generation pins may deliberately change generated bytes.
