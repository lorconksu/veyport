# Private evidence collector

This collector pulls recipient-encrypted reports from GitHub, verifies authenticated run and artifact identities, validates the complete bounded manifest, and archives encrypted content-addressed blobs on the operator's NFS mount. It never executes submitted code. Its signed receipt acknowledges archival only; scanner results, policy evaluation, candidate qualification and publication remain separate gates. DAST remains deferred.

Runtime: Linux with Python 3.11+, Debian `age`, and OpenSSL 3. Signature messages use bounded, rewound and sealed Linux memfd descriptors passed explicitly to OpenSSL, with no named plaintext signing file or disk fallback. The age CLI is a deliberate additional dependency: reviewed X25519/ChaCha20-Poly1305 recipient encryption replaces any bespoke crypto protocol; upstream is BSD-3-Clause, with Debian maintenance/security updates. OpenSSL supplies Ed25519 signatures. Python dependencies are standard library only. Keep package security updates enabled. Reports and manifests remain age-encrypted on the unencrypted NAS dataset; report plaintext exists briefly in collector memory and private temporary files, so configure memory-backed private `/tmp`, disable swap/core dumps, and protect the container disk/backups. Indexes contain run identity, hashes, retention deadlines and ciphertext digests only.

## Workflow contract

The manifest is UTF-8 JSON, schema 1, canonicalized using Python `json.dumps(value, sort_keys=True, separators=(',', ':'), ensure_ascii=False, allow_nan=False)`. Duplicate JSON keys are rejected. Required fields:

```json
{"schema":1,"repository":"lorconksu/veyport","workflow":".github/workflows/release.yml","run_id":123,"run_attempt":1,"revision":"0000000000000000000000000000000000000000","candidate_id":"release-123-1","complete":true,"files":[{"name":"reports/policy.json","sha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","size":42}],"details":{}}
```

`details` contains the exact candidate inventory/digests, policy revision, scanner/configuration identities, findings/approvals, outcomes and coverage. The release evaluator owns its schema and decision. Every byte of `details` is included in the acknowledged manifest hash. `complete:false` is durable diagnostic evidence and never satisfies `wait-receipt`. The collector does not infer scanner completeness from an empty inventory. Files must be sanitized before sealing: exclude tokens, passwords, synthetic account secrets and raw sensitive authentication transcripts.

```bash
python3 infra/evidence-collector/evidence.py seal \
  --manifest manifest.json --source reports-root \
  --recipient collector-recipients.txt --output upload/evidence.age \
  --hash-output manifest.sha256
```

Upload **only** `upload/evidence.age` using `actions/upload-artifact` under the exact name `ssdf-evidence-v1-${{ github.run_id }}-${{ github.run_attempt }}`, with a seven-day temporary retention. No plaintext report or manifest goes in the Actions artifact. Default hard limits: 256 file entries, 16 MiB per file, 64 MiB total payload, 1 MiB manifest, bounded archive/crypto/API sizes and deadlines. Do not use this interface for multi-GB candidate binary transport. Candidate transfer/deployment needs its separate reviewed coordinator.

Keep original candidate bytes in the same trusted release job, evaluate all gates, and wait for the receipt before publication:

```bash
python3 infra/evidence-collector/evidence.py wait-receipt \
  --repository lorconksu/veyport --run-id "$GITHUB_RUN_ID" \
  --attempt "$GITHUB_RUN_ATTEMPT" --revision "$GITHUB_SHA" \
  --manifest-sha256 "$(cat manifest.sha256)" \
  --public-key collector-receipt-public.pem --timeout 600
```

The default receipt transport is a commit status with context `ssdf-archive/<run>/<attempt>`, description `Archived sha256:<complete-manifest-hash>`, and signed JSON encoded in the fragment of a pinned GitHub run URL. The fragment contains no reports, private endpoint, credentials or candidate inventory. `wait-receipt` retrieves authenticated statuses with `GITHUB_TOKEN` and verifies the Ed25519 signature with an independently pinned public key, exact repository/run/attempt/revision/full-manifest hash, complete flag and archival timestamp. A green GitHub status alone is insufficient. Receipt signatures also bind the exact source artifact ID/name/digest tuple and a digest of the stored ciphertext inventory, which the cleanup role verifies without needing the age identity. Key replacement requires a reviewed public-key pin update; key recovery/rotation is an operator responsibility.

## Deployment

Provision a dedicated unprivileged LXC, 2 CPU/1 GiB RAM, collector UID/GID 1000 (host 101000). Host mounts the private NFS export and binds only the Veyport dataset root at `/var/lib/veyport-evidence/archive`. Install this directory's code at `/opt/veyport-evidence`, root-owned and not writable by the collector. Install units in `/etc/systemd/system`. Copy the example to root-owned `/etc/veyport-evidence/collector.json` and replace operator values. Do not commit live configuration, NAS access details or credentials. The example source must match the actual mountinfo source exactly. Trusted source revisions must be reachable from the immutable resolved default-branch commit, and workflow/security-helper blob identities must match that trusted tree. Bounded immutable Git commit/tree snapshots compare all helper identities in two recursive tree responses, with truncation rejected; an identical source/default-branch commit needs only the branch lookup. The collector does not spend one API request per helper or raise its polling budget to hide stalled progress. Before merge, an operator can explicitly pin the exact 40-hex reviewed rehearsal revision in `approved_source_revisions`; the pin covers its immutable entire tree and never grants general feature-branch trust. Remove rehearsal pins after use.

Before enabling the timer, the operator supplies all of the following:

- A `.archive-id` file in the dataset root containing the same operator-selected UUID as `archive_id`. Make it root-owned/read-only where supported. The sentinel is an identity check, not immutable retention.
- An age identity with a tested independent recovery copy, its recipient file and documented rotation procedure. The collector needs decrypt access; GitHub receives only the public recipient. Never copy the private key into a workflow.
- An Ed25519 private signing key and corresponding PEM public key, provisioned privately. Pin the public key in the trusted release workflow.
- A repository-scoped token with Actions read, Contents read and commit-statuses write. A fine-grained token avoids a GitHub App key requirement. A separate cleanup identity holds Actions write and Contents read; this implementation verifies local signed receipts and does not require commit-statuses permissions for cleanup. No broad personal OAuth token is installed persistently. Missing credentials fail the service; an unconfigured collector cannot authorize publication.
- A private memory-backed temporary directory, no core dumps or unencrypted swap, current package updates, and monitoring of timer failures, token expiry, NAS capacity, collection lag and artifacts nearing their seven-day expiry.

Run `evidence.py preflight --config /etc/veyport-evidence/collector.json` as UID1000. It checks exact NFS filesystem/source/mountpoint and marker, pins the mount's open directory descriptor, writes an innocuous probe with fsync, reads it back and fsyncs the directory. It replaces one fixed innocuous probe; repeated timer preflight does not accumulate probe files. A missing/remounted/wrong filesystem fails closed; an unmount cannot redirect descriptor-pinned writes into the local mountpoint. Configure the underlying host mountpoint non-writable to host101000 as another safeguard. An NFS server outage can block a hard-mounted operation; systemd timeouts are not a substitute for NAS monitoring and hard-mount availability recovery.

Run a supervised encrypted test-bundle rehearsal before enabling `systemctl enable --now veyport-evidence.timer`. Verify actual mount-loss rejection, restore the mount, verify decrypt/readback and recovery from the separate key copy, check the public receipt and restart idempotence, then perform an exact test-artifact deletion with the cleanup identity. Initial deployment without the narrowly scoped GitHub credential can verify local archive/crypto only; collection/receipt/publication remain blocked.

## CI chunks and sanitized terminal logs

Every CI job encrypts bounded report parts before uploading `ssdf-job-v1-<run>-<attempt>-<logical-job>`. The configured allowlist covers unit, six server shards, frontend tests, integration, smoke, E2E, Sonar, SAST, secrets and vulnerability jobs. The collector discovers these independently of workflow finalization, verifies exact artifact ID/run/revision and archive digest, and processes up to 64 encrypted chunks/512 MiB per job. Encrypted ZIPs spool only to a private mode0700 operator-provisioned `transport_spool` with at least 576 MiB free; create `/var/lib/veyport-evidence/spool` owned by UID/GID1000 mode0700 and grant only that additional path in the systemd service `ReadWritePaths`; report plaintext stays bounded in private temporary memory/files before age archival. Each chunk is at most 8 MiB of retained parts and uses the regular manifest schema with `complete:false`, `details.kind:job-chunk`, exact logical job/index/count, event `github_sha` and actual `checkout_revision`. Original-file metadata distinguishes retained redacted bytes (`sha256`,`size`) from the original source fingerprint (`original_sha256`,`redacted`), with exact offset/size/hash/chunk references for reconstruction.

All available original report parts are stored as deduplicated encrypted blobs. The collector reconstructs and hashes complete originals without retaining another plaintext copy, and records missing chunks/originals explicitly. A private signed per-job summary acknowledges the entire available chunk/ciphertext/child-manifest inventory and archived reference closure. Child chunks cannot authorize deletion: only the complete job-archive receipt carries its upstream artifact ID. Untrusted PR source may be archived as authenticated platform-origin data with `source_trusted:false`; it never satisfies release qualification or a complete release archive receipt. No submitted code is executed.

Terminal GitHub job logs are also recovered independently through the authenticated per-attempt job listing and plain-text log endpoint. Each job's exact ID/run/revision is checked; the attempt is bound by the requested attempt endpoint (GitHub's job response need not include a run_attempt field). Raw and retained log sizes are bounded to 64 MiB/job. Collector-owned sanitization removes recognized password/secret/TOTP/token/cookie/authorization fields, provider credentials, JWTs, signed query credentials and private-key PEM blocks before storage; it retains separate raw fingerprints and sanitized hashes. No raw log text or redirect URL is printed. Signed HTTPS redirects never receive GitHub authorization and cannot redirect onward. Recognized credential removal complements GitHub masking and producer redaction; arbitrary unknown credentials cannot be reliably identified from all free text. Missing/expired/oversized logs receive explicit incomplete records, remain retryable and cannot satisfy a complete release receipt.

A complete release/staging archive acknowledgement requires the fixed 14 same-run/attempt/revision CI jobs (SAST executes in delivery), independently successful terminal GitHub job metadata, privately signed complete report archives, and their signed sanitized terminal-log archives. Sender `details.expected_ci_jobs` must match collector policy and cannot waive a required job. The final release index includes every CI report/log part and job summary in its protected reference closure. The public signature binds the complete release manifest, stored ciphertext closure and `ci_jobs_sha256`, the hash of the exact job/report+log manifest identities. Thus a verified publication deadline, or an unresolved-publication deletion hold, protects the full CI reference closure independently of GitHub expiry. An archive receipt still makes no scanner policy or candidate qualification claim.

## Retention, reconciliation and deletion

Collection polls recent runs independently of workflow finalization. Per-poll API budget defaults to 60 calls, with a rate-limit reserve; completed outcome records are not fetched repeatedly, and per-attempt lookups are shared. A 15-minute completed polling cache bounds repeated artifact discovery. Active/queued searches and a five-run round-robin historical audit discover old reruns; the collector fails explicitly if the configured historical scan cannot meet temporary retention. Durable backlog state and checkpoints preserve unfinished work on budget exhaustion, and budget failures never become complete evidence. Failed/cancelled runs without an artifact receive explicit incomplete manifests and no passing receipt; a later available artifact is collected separately. A durable discovery checkpoint, one-hour overlap, and explicit pending-run set cover long outages and attempts; discovery partitions by day and fails if the provider search cap could truncate a day. Set `initial_since` for a deliberate history import before the first start. An upstream artifact may expire before recovery: record missing evidence, alert and recover from the vendor/source where available; absence never becomes a clean report. Monitor storage headroom for retry copies. Seven-day GitHub retention reduces occupancy but cannot recover previously accrued charges or guarantee indefinite recoverability.

Each run/attempt/manifest has its own index. Identical report bytes use one age-encrypted blob; every active reference protects the blob. Completed ordinary runs retain 180 days from completion (conservative GitHub `updated_at`), and a revision bound to an independently audited publication extends to at least the calendar-year anniversary of publication. Nonterminal records remain protected. Authenticated release reconciliation runs before deletion/retention; GitHub outages fail closed. Previously recorded retention deadlines never shorten if a release/tag changes, but an observed current tag target is never treated as proof of the original published revision. Leap-day publication retains through February 28 of the following year.

Published-release identity must be resolved before any archive retention or upstream artifact deletion. The collector records published release ID and exact `published_at`, without querying a mutable tag or trusting `target_commitish` or a replaceable release asset. `state/publication-hold.json` exposes a repository-wide deletion hold while any observed publication is unresolved; collection, final-outcome reconciliation and durable archive acknowledgements continue. The hold also preserves unresolved releases later removed upstream. This is a conservative hold, not a claim that an unverified revision has received a one-year release deadline. GitHub's automatic temporary-artifact expiry still applies independently.

Normal publication is resolved automatically by `ssdf-publication-v1-<run>-<attempt>`: a recipient-encrypted, source-authenticated postpublication manifest links exact release ID/publication time from the publication API operation's own response to the already signed complete prepublication archive and candidate inventory. The collector verifies trusted immutable workflow source, exact run/attempt/revision/artifact identity, archived receipt/storage/candidate/chronology, then preserves the complete report closure and writes an independently signed private publication proof. Deletion/retention roles verify that proof with the public key and need no age identity or signing key. A moved tag, replaced summary asset or deleted upstream release does not change that proof.

Successful trusted release-workflow runs also create durable possible-publication signals even if the release was created and deleted before the first catalog poll. Staging runs are distinguished through the exact publishing-step metadata: a skipped private rehearsal is not called publication, while an entered publishing step requires a matching proof or audited run disposition. The run ledger survives source-record expiry. Catalog discovery reads, merges and writes under the shared archive lock; deletion rechecks the durable catalog and newly archived terminal runs under its own critical section, so a stale resolved snapshot cannot erase or bypass a newer hold.

Exceptional/historical mappings are currently pending operator audit. To resolve a publication, the operator supplies a private root-controlled `audited_release_publications` list shared by the collector/cleanup/retention configurations. Each record requires `release_id` (positive integer), exact provider `published_at`, immutable 40-hex `revision`, `provenance:"operator-audit"`, a bounded private `audit_reference`, and UTC `audited_at` at or after publication. Supply both positive `run_id` and `run_attempt` to resolve a known possible-publication run; revision-only similarity does not discharge a separate run signal. The reference must identify independently reviewed historical publication evidence; a current tag, mutable branch, free-text release target, or replaceable summary asset alone is insufficient. Conflicting/duplicate identities, malformed hashes/timestamps and unknown provenance are rejected. Explicit audited records can preserve historical publications already absent from the API. No mappings are generated or approvals assumed by this change. A missing, cancelled, expired or invalid postpublication transport leaves deletion on hold until its provenance is recovered or independently audited; successful normal transports require no recurring manual audit.

Legacy `state/releases.json` entries derived from tag lookup migrate into an unverified observation catalog. Their prior per-run deadline extensions remain intact, but cached tag observations do not become historical proof and cannot release the deletion hold without operator audit. Removing an audited mapping causes that publication to become unresolved again. Keep the hold under operator monitoring; it must never be cleared merely to reduce storage occupancy.

Run `cleanup --config PRIVATE-CLEANUP-CONFIG` only under the independent identity with Actions write and Contents read. It requires neither private age identities nor the signing key; commit-statuses access is unnecessary for local receipt verification. It requires a signed, exact-manifest archive acknowledgement, rereads and hashes the archived ciphertext inventory, confirms the exact artifact ID/name/digest/source run, and waits until all workflow jobs and any current rerun have completed. It deletes no release asset, workflow, unrelated artifact or candidate build artifact. Do not give artifact consumers in other workflows access to these dedicated transport artifacts; same-run consumers are checked automatically. It records deletion after acknowledgement and retries safely. Automatic upstream expiry can still occur without a collector receipt.

Run `retain --config PRIVATE-RETENTION-CONFIG` as the separate storage operator with `retention_enabled:true` and a read-only GitHub credential holding Actions read and Contents read. This role requires neither age nor signing keys nor the Actions-delete credential. It refreshes final outcomes/release deadlines, then removes expired per-run references under the shared NFS lock. Blobs/manifests remain protected until the latest referencing deadline; orphan ciphertext gets at least 180 days before cleanup. Never enable retention in the collector service configuration. NFS directory ownership may still permit collector unlink; strict append-only privilege requires tested NAS ACLs outside this application. This implementation claims application/credential separation, not WORM or immutable retention. NAS snapshots are separately scheduled recovery protection and must be restore-tested.

## Validation and public API references

Run `python3 -m unittest discover -s infra/evidence-collector -p 'test_*.py'` with age and OpenSSL available. Tests generate isolated throwaway fixture keys and never print them.

The REST integration follows GitHub's [artifact API](https://docs.github.com/en/rest/actions/artifacts?apiVersion=2022-11-28), [workflow run API](https://docs.github.com/en/rest/actions/workflow-runs?apiVersion=2022-11-28), and [commit statuses API](https://docs.github.com/en/rest/commits/statuses?apiVersion=2022-11-28). Signed artifact-download redirects are HTTPS allowlisted and never receive the GitHub Authorization header. Crypto format and supported recipient handling follow [age upstream](https://github.com/FiloSottile/age) and [OpenSSL pkeyutl](https://docs.openssl.org/3.0/man1/openssl-pkeyutl/).
