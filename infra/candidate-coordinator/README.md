# Isolated candidate coordinator

The coordinator consumes `ssdf-candidate-v1-<run>-<attempt>` encrypted Actions artifacts produced by `scripts/release/candidate.py`. It validates authenticated repository/workflow/run/ref identity and immutable source trust, streams bounded ciphertext over HTTPS without forwarding GitHub credentials to storage, verifies the Actions archive digest, decrypts to a dedicated private work directory, validates every file against the complete candidate manifest, and loads the exact scanned native OCI image into Docker. No artifact-supplied command, deployment template or source code controls the coordinator.

Runtime is separate from the evidence collector: install on the personal staging Docker host with its own operator configuration, age identity, native qualification signing key and repository-scoped Actions-read/Contents-read/commit-statuses-write token. Keep the private decryption identity outside GitHub and test its separate recovery copy. The public recipient is `SSDF_CANDIDATE_AGE_RECIPIENT`; the pinned native receipt public key is `SSDF_CANDIDATE_PUBLIC_KEY`. Do not enable polling without the dedicated token. Manual local rehearsal may exercise archive extraction, isolated runtime and native probes without a persistent token; it cannot claim a GitHub-authenticated end-to-end qualification.

Dependencies: Python 3.11+, Debian age, OpenSSL, Docker, skopeo, iptables, and the operator-installed external harness/probe from `scripts/native-candidate/`. age/OpenSSL have the same reviewed crypto justification as the evidence collector. Docker/skopeo are already used for exact OCI delivery; no Python dependency is added. Boundaries are 4 GiB total candidate bytes, 512 MiB/file, 1024 files, 1 MiB manifest/metadata, bounded ZIP/TAR processing, command deadlines and resource limits. Keep at least 12 GiB free before starting; allow additional space for Docker layers. Files remain private to the operator. Disable unencrypted swap/core dumps, protect staging disk/backups and use private temporary storage.

## Runtime and isolation

Create the dedicated Docker network `veyport-candidate-internal`, internal bridge `br-vey-cand`, with label `io.veyport.ssdf=qualification` and an independently verified nonconflicting subnet. The coordinator requires the exact operator-pinned `docker_network_id`, configured `docker_network_subnet`, internal networking, bridge driver/label and the `br-vey-cand` bridge option. A same-name network recreated on another bridge cannot bypass the verified firewall hooks; the same network ID is rechecked during qualification. Docker 29 suppresses published ports on internal networks, so the host harness uses only the exact current candidate bridge IP independently verified from Docker inspect, on container ports 8081 HTTP, 9090 gRPC and 2222 SSH. No candidate host port is published while DAST is deferred. Normal staging's container, ports, database and volumes remain independent. The candidate gets its own disposable data directory, a read-only root filesystem, no capabilities, no privilege escalation, bounded CPU/memory/PIDs, and only its data bind mount. The original OCI config digest is bound by `reports/veyport.scan-binding.json`. The coordinator converts through a private docker-archive, uses the installed Docker CLI to load/save by exact image ID, and inspects the saved archive offline. This avoids the older skopeo docker-daemon SDK incompatibility with Docker 29 without changing daemon APIs. Both temporary conversion archives are removed after verification. Docker import can reserialize config JSON and change the image ID; the coordinator therefore verifies canonical equality of every source/imported config field, including every rootfs DiffID, command, history and label, and records the source config digest, actual runtime image ID and canonical config hash as an explicit conversion binding. Version/revision labels and before/after runtime identity must match. Any semantic configuration or rootfs change fails; original OCI archive bytes stay unchanged for publication.

Install `firewall.py` and `veyport-candidate-firewall.service` at `/opt/veyport-candidate` and `/etc/systemd/system`. The service creates only the dedicated `VEYPORT-CAND` chain: accept established/related traffic, then drop. It inserts narrow first-position INPUT and DOCKER-USER hooks for the dedicated candidate bridge. New candidate traffic cannot reach host services or leave its bridge; same-bridge fixture traffic remains available. Existing mismatched chains or misplaced hooks fail verification instead of flushing host rules. Verify actual gateway/private-network/Internet denial with a disposable unprivileged pinned image before setting `network_isolation_verified:true`; rule presence alone is not that runtime proof. Reverify after Docker/firewall restarts. Do not start candidate code if isolation is missing.

Copy and complete `config.example.json` privately. Install coordinator.py and the evidence collector's trusted evidence.py at their corresponding sibling paths under `/opt`; the coordinator imports only those installed files. Set `hub_uid`/`hub_gid` from the reviewed image and `agent_runtime_image` to a separately provisioned exact Debian fixture image ID (the candidate does not select/pull it), pin the deployed root-owned harness and compiled probe SHA256 values, and configure the exact fixed native case IDs from the harness. An empty required-case policy fails closed. Root-owned code/configuration must not be writable by candidate containers. `approved_source_revisions` permits only an explicitly reviewed immutable rehearsal commit before merge; it grants no general trust to feature branches. Production source must descend from the trusted default branch and match the current trusted workflow/security helper blobs.

The native harness receives private runtime JSON with candidate/source/inventory identity, image/container identity, exact inspected candidate endpoints, internal Hub alias, actual verified agent/CLI binary paths/digests, and disposable work/data directories. Synthetic authentication secrets and raw probe transcripts live under a private memory-backed `native_tmp_root` and are removed after each harness invocation. All candidate files, including private reports, are hashed and verified during extraction; report bodies are discarded rather than persisted. Only the Hub OCI archive, native agent/CLI binaries and minimal OCI configuration/binding metadata are retained on private scratch disk. That scratch disk is not claimed encrypted; final evidence payloads are age-encrypted independently. It bootstraps real synthetic accounts and enrollment through candidate APIs, runs the actual hash-verified candidate agent bytes in its disposable fixture and verifies the CLI digest (CLI execution checks run elsewhere) (allowlisted extracted native binaries receive 0700, never supplied SUID/modes; the agent is mounted read-only into the pinned support image), and tests gRPC/SSH behavior against the actual installed Hub. Source test fixtures never satisfy runtime qualification.

## Audit profiles and receipts

This prototype uses `audit_profile:standard`, matching the normal default and the plan's mode-dependent audit requirements. The manifest, operator configuration, harness report and signed receipt must agree. Standard requires genuine required-audit admission failure plus recovery proof against the disposable candidate, with `required_audit_admission_exercised:true` and `enhanced_receipt_exercised:false`. The harness may inject a narrowly scoped SQLite audit-insert failure in only the labeled disposable Hub's database, remove the fault in a finally block and prove denied command markers never appeared. This is not an Enhanced external receipt test. Existing Enhanced source/integration fixtures remain complementary CI coverage.

If `audit_profile:enhanced` is selected, the live external receipt failure fixture must execute and `enhanced_receipt_exercised:true` is mandatory. Missing provisioning, skipped cases, scanner errors, incomplete authentication, mismatched identities or any required case failure cannot produce qualification. There is no Standard fallback. DAST remains explicitly deferred.

A successful complete runtime report is reduced to a fixed disclosure-safe summary before signing. Public commit statuses contain candidate/source/inventory binding, profile, case IDs/pass, scope coverage and a 30-minute qualification deadline; no endpoints, synthetic account identifiers, credentials, raw diagnostics or private work paths. The structured private native result remains in the private candidate work directory, while raw transcripts and synthetic secrets are removed with the private temporary fixture; the workflow archives the disclosure-safe policy report in encrypted final evidence. The signature covers the entire receipt and exact candidate manifest digest. The release job verifies the pinned public key, expected profile, source and candidate identity, policy, current deadline and unchanged original bytes immediately before publication.

The exclusive local lease prevents overlapping candidates. The coordinator rechecks container/image identity and all candidate file digests after testing, and queries GitHub again before acknowledging so cancellation, rerun or revision changes fail closed. Per-attempt durable state prevents duplicate qualification and automatic lease extension; an expired qualification needs a new workflow attempt. Private result state is fsynced before acknowledgement. Candidate containers are removed by exact verified identity in finally. Keep private diagnostics for failure review; apply a separate operator work-directory retention procedure only after final outcome/evidence archival, and monitor storage headroom. Interrupted processes may leave a labeled stale container: inspect its exact identity and synthetic directory before operator cleanup. No wildcard container/image/volume deletion is implemented.

The collector's archive receipt remains separate: candidate qualification does not acknowledge durable NAS evidence, and an archive acknowledgement does not prove qualification. Both gates are required for publication.
