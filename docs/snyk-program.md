# Snyk program maintenance

Veyport receives security tooling support through the
[Snyk Secure Developer Program](https://snyk.io/open-source/).
William Yiu is responsible for reviewing continued eligibility.

## Current record

Verified on 2026-10-30:

- The repository is public and licensed under Apache-2.0.
- The maintainer confirmed that Veyport is independently maintained with no
  corporate backing, and that Snyk's co-branding permission was already accepted
  during enrollment. Keep the original approval and agreement in the private
  maintainer records; do not commit account credentials or private correspondence.
- GitHub's configured project homepage is the public
  [Veyport wiki](https://github.com/lorconksu/veyport/wiki).
- Acknowledgments are maintained in `README.md` and `docs/wiki/Home.md`.
  The wiki-sync workflow publishes the latter after changes reach `main`.

The accepted program agreement is separate from the public
[trademark policy](../TRADEMARKS.md). This document does not grant new branding
rights to other parties or change the software license.

## Continued eligibility

Snyk's published criteria require no corporate backing, a link to Snyk in both
the repository README and project website, and permission to display project
branding and related content. Program entitlements cover eligible open-source
projects only, excluding corporate and non-open-source projects. Recheck the
[current criteria](https://snyk.io/open-source/) when circumstances change.

Use this checklist before releases and changes to ownership, funding, the
website, or connected repositories. This is Veyport's maintenance practice,
not a renewal schedule specified by Snyk:

- Verify that the public default-branch README and live wiki homepage both
  retain a working `https://snyk.io/` acknowledgment. Check the live pages after
  merge; an unmerged branch alone does not publish the links.
- If a separate project website replaces or supplements the wiki, include the
  acknowledgment there too and update this record. Seek clarification from Snyk
  if its interpretation of the project website is uncertain.
- Review any changes to ownership or financial support against the program
  criteria before relying on the entitlement.
- Keep the enrolled Snyk organization and connected repositories scoped to
  eligible projects. Review new repository imports and integrations; do not
  use this entitlement to scan private employer or customer projects.
- Retain the program approval and co-branding agreement privately. Revisit
  them when the project name, logo, or ownership changes.
- Check the Snyk organization settings and any renewal or eligibility messages
  for continued program activation. A passing GitHub check does not verify
  the organization's subscription entitlements.

Snyk determines program eligibility. This checklist supports maintenance; it
does not replace the accepted agreement or independently verify account-level
entitlements.
